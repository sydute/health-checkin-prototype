「体重天天打卡」小程序拆解与网页原型对照分析

分析依据：用户提供的 10 张真实截图（2026-10-28）｜原型地址：weight/index.html｜截图未覆盖的页面已明确标注推断

一、产品概览

  • 产品名称：小程序内显示为「瘦身打卡助手」（用户侧入口名「体重天天打卡」）
  • 定位：个人体重记录工具 + 轻社交激励（排行榜 / 组队PK / 分享）
  • 核心闭环：每日打卡 → 日历留痕 → 趋势/分析反馈 → 目标进度激励 → 社交扩散（分享/组队/排行榜）
  • 底部 Tab（4 个）：体重（首页）、排行榜、组队PK、我的

三、核心交互流程还原

流程 A：首次打卡主链路

首页「今日打卡」 → 首次记录弹层（身高/当前体重/目标体重 + 提醒勾选 + 提醒时间） → 「开始记录」（体重为空或 ≤0 → Toast 拦截，不离场） → 打卡成功弹窗（体重 + BMI + 本月统计 + 激励语） → 三个出口：查看数据分析（→P7）/ 分享给好友（微信分享）/ 关闭 → 关闭后触发「添加到桌面」引导弹窗（→ 知道了） → 回到首页：日历当天出现体重标记，今日体重卡更新

流程 B：重复打卡拦截

首页「今日打卡」（当天已有记录）→ Toast「今天已打卡，明天再来」，不打开录入窗

流程 C：查看与维护记录

首页日历卡「全部记录」→ P6（默认本月） → 切换 今年/全部 Tab 改变统计口径与列表粒度（日 → 月 → 年） → 本月态下条目「删除」→ 记录移除，日历与统计同步清空 流程 D：BMI 科普：首页 BMI 胶囊 → BMI 中国标准弹窗 → 知道了 流程 E：目标管理：首页「本月目标」→ 编辑弹窗 → 保存 → 进度/差额即时重算 流程 F：提醒开关：我的 → 打卡提醒 → 开启后副文案变为「已开启 09:00」

反馈与异常机制

  • 空态策略统一：趋势图/曲线/趋势细节均要求 ≥2 条记录，不足时显示引导文案而非空图表
  • 变化量策略：仅 1 条记录时所有「变化」展示「暂无变化 / --」，并附「保持观察」安抚徽标
  • 校验拦截：必填体重缺失时 Toast 提示，停留在当前弹层
  • 反馈时效：弹窗开合均有过渡动画；打卡成功即时给出统计反馈，无加载等待

六、可优化点与落地建议

原小程序自身可优化的点（评测视角）

  • 首条记录后几乎所有面板都是空态：趋势、变化、建议同时显示"暂无数据"，首打卡后的成就感被稀释。建议：首条记录即展示「与目标的差距」「BMI 定位」等单点可算指标，让成功弹窗后的首页有内容变化。
  • 「保持观察」语义模糊：变化卡的状态徽标可改为更明确的「数据积累中（1/2）」进度式表达，用户知道再记一次即可解锁曲线。
  • 本月变化长期为「--」：月内无变化时可退化为展示「较首次记录」，更早给出反馈。
  • 删除入口过浅且无二次确认迹象：体重记录误删成本高，建议删除增加确认弹窗 + 删除后 5 秒撤销。
  • 打卡提醒依赖订阅消息：「未开启」状态在我的页曝光不足，建议在首页打卡按钮区做轻提醒。
  • BMI 弹窗缺少身高/体重的快捷修正入口：读数异常时用户需跳出多级页面修改。

网页原型落地为真实网页产品时的建议

  • 补齐推断页截图：排行榜、组队PK、月度报告、个人信息页拿到真实截图后校准布局与字段。
  • 分享链路替换：小程序分享卡片 → 网页端改为生成打卡海报图（Canvas）+ 复制链接。
  • 提醒能力替换：订阅消息 → 邮件/浏览器 Notification + 日历订阅（ICS）。
  • 数据可视化升级：网页端屏幕更宽，趋势图可扩展为体重+BMI 双轴曲线，趋势细节卡可列表化展示每日记录。
  • 单位体系：保留斤/kg 双显，设置中增加默认单位切换。
  • 打卡照片：记录页已有「有照片/显示照片」筛选与开关，说明原小程序支持打卡附图；网页端可直接复用本仓库已有的相册/拍照上传组件实现。

七、v2 原型优化改进说明（已落地）

基于第六章评测结论与 10 张截图反映的设计差异，对原型进行了系统性体验升级（weight/index.html 已更新为 v2）。改进范围严格遵守限定：未新增排行榜、组队PK、最新活动、微信机器人、在线客服、关于我们 6 项内容，底部 Tab 与我的页菜单保持原样（排行榜/组队PK Tab 仍为「截图未提供·推断」占位）。所有调整均围绕现有核心功能的体验升级，核心框架不变。逐项说明如下：

改进项具体调整内容优化原因（对应第六章问题）
1. 数据真实化演示 内置 3 条演示记录（10-22 / 10-25 / 10-28），首页本月趋势卡渲染真实 SVG 折线图（面积填充 + 圆点 + 目标虚线 + 日期轴）；本月变化由「--」变为真实差值（-1.0斤，红绿配色区分增减）；日历上对应日期显示体重标记 解决「首条记录后几乎所有面板都是空态、成就感被稀释」的问题，打开原型即有完整内容可评审
2. 空态改为进度式引导 记录 <2 条时，趋势空态文案改为「已记录 n/2 天，再记录 x 次即可生成趋势图」，并附「去记录今日体重」行动按钮 替换「保持观察」模糊语义，用户明确知道还差几步解锁曲线，空态从"死路"变成"引导"
3. 删除保护：确认 + 撤销 记录页点「删除」先弹确认框（显示将删除的日期与数值）；确认后记录移除，底部弹出 5 秒 Toast 提供「撤销」，点击即恢复原记录并联动日历/统计刷新 体重记录误删成本高，原小程序删除无二次确认；双重保护显著降低误操作损失
4. 提醒前置曝光 首页今日体重卡上方新增提醒横幅（未开启时显示「开启每日提醒…」），点击直达提醒设置；我的页「打卡提醒」打开完整设置弹层（开关 + 07:00~21:00 六个时间快捷选择），开启后首页横幅自动消失、我的页副文案变为「已开启 xx:xx」 原小程序提醒入口深埋在「我的」页，「未开启」曝光不足；前置横幅把留存工具放到打卡动线起点
5. BMI 弹窗补修正入口 BMI 中国标准弹窗底部新增「修改身高 / 体重 ›」链接，直接打开身高/体重编辑弹层；保存后 BMI 值、等级、色带指针、首页 BMI 胶囊全部即时重算 原小程序读数异常时需跳出多级页面修改；新增快捷入口把"发现异常→修正"路径缩到 1 步
6. 表单校验体系升级 首次记录/编辑/身高体重等全部数字输入改为实时校验：非法值（非数字、超出身高 100-250cm / 体重 30-300斤 范围）输入框红框 + 就地错误文案 + 主按钮禁用；目标体重 ≥ 当前体重时提示「进度会一直为 0%，建议设低一点」 原小程序仅在提交时 Toast 拦截，用户不知错在哪；实时校验把错误定位到具体字段，减少试错
7. 记录可修改 今日已打卡后，「今日打卡」按钮变为「✎ 修改今日」；记录页条目点击可打开编辑弹层修改体重数值（复用同一弹层组件，区分「记录」与「修改」标题） 手滑输错体重是高频场景，原流程只能删除重记；允许修改保留记录连续性，避免趋势图断点
8. 打卡成功弹窗真实数据 成功弹窗三格统计（本月已打卡 / 本月变化 / 距目标）由写死文案改为按当前数据实时计算 反馈即时性与真实感是激励的核心，假数据会削弱"记录被认真对待"的感受
9. 分析页动态化 评分环按打卡天数计算（min(100, 天数×7)）并用 conic-gradient 渲染；状态文案分五档（还没有开始/刚刚开始/渐入佳境/稳定坚持/自律达人）；建议区按数据量动态生成；打卡习惯条形图按真实记录统计各星期次数 分析页是用户坚持的主要回报，静态占位会让"分析"名不副实；动态化后每个数字都可溯源

交互逻辑变更摘要

  • 删除链路：删除 → 确认弹窗 → 移除 + 5 秒撤销 Toast（原：删除直接移除）
  • 提醒链路：首页横幅 → 提醒设置弹层（原：仅我的页入口）
  • BMI 链路：BMI 弹窗 → 修改身高/体重弹层 → 全站 BMI 重算（原：弹窗为只读）
  • 打卡链路：今日已打卡 → 按钮变「修改今日」→ 编辑弹层（原：Toast 拦截后无路可走）
